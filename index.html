    Case study: PDTS

    The problem

    PUP Open University students send admission, masteral, comprehensive exam and deficiency documents to the Registrar's Office, many by courier from across the country. Tracking was manual, so students couldn't tell what had arrived or what was missing, and staff answered the same follow-up questions over and over.

    The solution

    • Checklist templates per purpose. Head Admins define the required documents for each purpose; officers tick them off as they verify each one.
    • Tracking references and process slips. Every submission gets a reference number and a printable slip.
    • Automatic emails. Any change in a submission's status emails the student, including exactly which document is missing.
    • Audit log. Every staff action is recorded with who, what and when, and can't be edited.
    • Web and Android. The same React app ships as a website and, through Capacitor, as an APK for tablets at the counter.

    Architecture

    React + TypeScriptWeb app (Vite)
    Android APKCapacitor wrapper
    ⇄
    Express APINode.js · RBAC · bcrypt
    ⇄
    PostgreSQLDrizzle ORM
    Email serviceNodemailer

    Hard parts I solved

    • Password security without breaking old accounts. Moved staff passwords to bcrypt; legacy plaintext rows are re-hashed automatically the next time that user logs in.
    • HTTPS on a local network. Set up trusted certificates with mkcert so the registrar's machines and tablets connect securely.
    • Android quirks. Fixed the app drawing under the status bar by configuring Capacitor's status bar plugin and Android styles.
    • Database structure. Normalized the schema, enforced foreign keys and wrote seed and reset scripts so anyone can set it up on Windows in one step.

    My role

    Project Leader. I led requirements gathering with the registrar, the system analysis and design documentation, the ERD and database, the full-stack build, the Android release, deployment and the final defense.

    Case study: Barangay Health Center Management System

    The problem

    Barangay health centers keep patient information in logbooks and folders. Staff copy the same details into several records for every visit, and finding a patient's history takes time.

    The solution

    • Patient registry with search
    • Consultation workflow from check-in to completion
    • Completing a consultation generates the patient's health record automatically
    • Full-width, responsive layout that works on the health center's desktop and tablets

    What I focused on

    Designing the flow so each step feeds the next: the data entered at check-in carries through to the consultation and into the health record without retyping. The project includes a review of related literature on health information systems from 2021 onward.

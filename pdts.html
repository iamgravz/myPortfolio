PDTS: document tracking for the PUP OUS Registrar's Office

Students of the PUP Open University System send their documents from all over the country. PDTS lets registrar staff log each one, check it against a requirement list, and email the student every time the status changes.

The problem

The Registrar's Office receives admission, masteral, comprehensive exam and deficiency documents, many of them by courier. Tracking was done by hand.

  • Students could not tell if their documents had arrived or what was still missing
  • Staff answered the same follow-up questions over and over
  • There was no record of who checked a document and when

What PDTS does

  • Checklist per purpose. Head Admins set the required documents for each purpose. Officers tick each one as they verify it.
  • Tracking reference and process slip. Every submission gets a reference number and a printable slip.
  • Automatic email. When the status changes, the student gets an email, including which document is missing.
  • Audit log. Every staff action is saved with who, what and when, and cannot be edited.
  • Web and Android. The same React app runs in the browser and, through Capacitor, as an APK for tablets.

Problems we worked through

  • Old passwords. Staff passwords were moved to bcrypt. Old accounts are re-hashed the next time the user logs in, so no one had to reset.
  • HTTPS on a local network. Trusted certificates made with mkcert, so the office computers and tablets connect securely.
  • Setup on Windows. Seed and reset scripts so the database can be set up in one step on a new machine.

My part

I led the group from requirements to the final defense. My own work was the database, setting the system up on Windows, building the Android APK, and the documentation.

What I learned: a system is only useful if the staff can install it and trust it. Most of my time went into setup, security and clear documents, not just features.
